## 1. 任務（從後端能力推導，不是從現有版面推導）

管理端後端有 **42 個 `/admin` 端點** + 外部 AI + 問題回報。依端點分佈歸納，
管理者實際在做的事只有五類：

| 類 | 端點群 | 現在散在哪 |
|---|---|---|
| **看有沒有出事** | `cluster`、`gpu-nodes`、`jobs`、`storage` | 管理介面 + GPU 節點 + 數據分析 |
| **處理某一個人** | `users`(9)、`quota`(3)、`secrets`、`lab`、`lab-archives`(3) | 帳號管理 + Lab 管理 |
| **調平台設定** | `system-settings`、`models`(4)、外部 AI | 管理介面 + 外部 AI |
| **回答問題** | 問題回報、`email-log`、`audit` | 問題回報 |
| **查數字** | 數據分析、MYAI 交易 | 數據分析 |

🔴 **關鍵觀察：第一類與第二類的使用時機完全不同。**
「看有沒有出事」是**每天開機看一眼**，要一頁看完、不用點；
「處理某一個人」是**接到求助才做**，入口是搜尋，不是瀏覽。
現在這兩件事混在同一個「管理介面」分頁裡，所以那一頁又長又雜。

### 已排除

- **不做手機版。** 管理端是坐在電腦前做的事，九欄的表格在手機上怎麼排都是災難。
  只保證 1280px 以上好用，以下不壞掉（可橫向捲動）。
- **不做即時推播。** 現有的自動重新整理（10 秒）夠用，WebSocket 的維運成本不值得。

## 2. 結構

### 路徑與檔案（沿用使用者端的並存前例）

```
admin-ui/          → 8888 埠的 /         （不動）
admin-ui-v1.5/     → 8888 埠的 /v1.5/    （不動）
admin-ui-v2/       → 8888 埠的 /v2/      （新增）
```

nginx 的 8888 server 加一個 `location ^~ /v2/`，寫法與使用者端 `/v2/` 完全一致
（含 `add_header Cache-Control "no-cache"` —— `?v=` 版號寫在 index.html 裡，
HTML 一舊版號就失效，這個坑踩過）。compose 加一條唯讀掛載。

### 分頁 → 分檔

**七個分頁改成五頁**，一頁一個 HTML + 一支 JS（與使用者端 v2 同構）：

| 新頁 | 併入了 | 為什麼 |
|---|---|---|
| `index.html` 總覽 | 管理介面的即時監控 + GPU 節點狀態 + 全域任務 | 「開機看一眼」的東西集中到這裡，**不需要點任何東西** |
| `people.html` 人 | 帳號管理 + Lab 管理 + 額度 | 都是「處理某一個人」，入口是同一個搜尋框 |
| `platform.html` 平台設定 | 系統設定 + 模型管理 + 外部 AI + GPU 節點時段 | 都是「調完就走」的設定 |
| `reports.html` 回報 | 問題回報 + 寄信紀錄 + 稽核 | 都是「回答問題」時要查的 |
| `analytics.html` 數據 | 數據分析 + MYAI 交易 | 維持獨立，它是唯一需要圖表的 |

⚠ **這是本文最需要你裁定的一項。** 併頁會改變你現在的肌肉記憶。
若你偏好維持七頁一對一搬過去，說一聲，那條路風險更低但不會解決「管理介面那頁又長又雜」。

### 共用檔

`tokens.css` / `i18n.js` / `prefs.js` / `tz.js` 需要在 `admin-ui-v2/` 各放一份
（nginx 的 alias 是不同根目錄，跨不過去）。

🔴 **重複的檔案一定要有機械檢查**，否則必然漂開。
`tz.js` 已有 `check_timezone.py` 守著五份逐位元組相同，照同一個模式擴充即可。

### 外部 CDN

四個全部拿掉：
- `chart.js` → 改成自繪 SVG（使用者端 v2 的圖表就是自繪的，沒有相依）
- ionicons / Material Icons → 改成內嵌 SVG（只用到的那幾個）
- Google Fonts（Playpen Sans）→ 不再需要

理由不是潔癖：圖書館若對外連線受限或 CDN 掛掉，**圖表與圖示會直接壞掉**，
而管理端正是出事時要用的東西。

## 3. 視覺系統

### 沿用（不重新發明）

`tokens.css` 兩層架構、黃／藍兩色系、字級用百分比且 root 不可釘 px、
所有色碼只出現在第 1 層 —— 全部照搬使用者端 v2，一個值都不改。

### 管理端要補的 token

使用者端沒有「密集表格」這種東西，所以要補一組：

```
--table-row-h        表格列高（比使用者端的卡片緊）
--table-border       列分隔線
--table-head-bg      表頭底
--density-*          兩級密度（寬鬆／緊湊），管理者自己切
```

### 圖表

現在是 **Chart.js 預設樣式直接放進去**：灰底、預設藍綠、預設圖例，
與頁面完全沒有整合。改成自繪 SVG 後用 v2 已經算好對比的圖表色
（`--mcu-chart-*`，都是實算的 WCAG 值不是估計）。

🔴 **順帶要修一個內容問題**：「帳號狀態分佈」現在是**一整片單色的圓餅**
（只有一個分類「確定」佔 100%）。圓餅在只有一個分類時不傳達任何資訊，
而且那個標籤看起來是狀態值對應錯了。**這是資料問題不是版面問題**，
依鐵則 2 另外開一項查。

### 字體

`'Times New Roman', '標楷體', serif` → 改成與使用者端一致的 Open Sans + 微軟正黑。
理由：儀表板的大數字（例如總點數 45,408,539）用書法字體讀起來吃力，
而管理端有大量數字與代號要快速掃視。

## 5. 未解與風險

- **併頁的風險是你的肌肉記憶。** 我可以做，但你才知道自己平常怎麼用。
  第 2 節那張表請逐列看過。
- **4913 行的 admin.js 要拆。** 拆的過程一定會漏掉一些只在特定情境跑的分支
  （這個 repo 已經因為「呼叫端沒帶參數」壞過七次）。
  對策：拆完之後**逐分頁實際點過**，不靠讀程式碼判斷。
- **舊版會慢慢沒人維護。** 三版並存的代價使用者端已經在付了
  （`09-ui-version-comparison.md` 那份對照文件就是為此而生）。
  管理端變成三版之後，建議在新版被信任後就訂一個關掉舊版的時間。
- **無障礙目前幾乎是零**（`aria-label` 1 處）。新版會補，但我沒有螢幕閱讀器可實測，
  只能做到結構正確（語意標籤、焦點順序、對比值），**不能宣稱通過**。
