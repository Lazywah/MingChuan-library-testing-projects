# 使用者端介面 v2 設計

> 本文是 **v2 使用者端介面**的設計推導紀錄，走 `design-before-code` 的五階段流程。
> 與既有的 `web-ui/`（v1）與 `web-ui-v1.5/` 的關係：**取代候選**。
> v2 另建新檔（`web-ui-v2/`），v1 與 v1.5 都不動，三版並行對照後再決定去留。
>
> 每一節都是通過使用者裁定後才寫入的。
> **實作狀態（2026-08-19）**：登入 / 首頁 / GPU 引導 / 使用量明細 / 開通確認 /
> Lab / 公告列表 / 問題回報 **八個畫面已完成**，各自獨立 HTML+JS，
> 共用 tokens.css 與 styles.css。首頁上每一個去處都有落點。
> 尚未實作：文件庫（規格訂為「有內容才出現」，目前無內容 → 入口正確地不出現）。

## 0. 前提

**舊設計的地位：保留鐵則，版面重來**（Decision Log #1）

### 鐵則（v2 必須遵守，不得推翻）

| # | 鐵則 | 來源 |
|---|---|---|
| 1 | **所有使用者（含 admin）的「AI 助手」導向 MYAI 廠商平台；v2 不設計內部 AI hub** | Decision Log #2 |
| 2 | 廠商端唯讀 —— 不呼叫 transfer/top_up/delete；交易日誌不存 IP | 資安界線 |

| 5 | 送 GPU 任務必須指定池別（高階 batch / 本地 interactive）與優先權 | 後端契約 |
| 6 | 點數／配額要看得到（外部 AI 點數來自廠商、GPU 有磁碟配額） | 使用者要知道剩多少 |
| 7 | 前端純靜態、只透過 `/api/v1` 取資料 | 架構約束 |

### 使用資料（推導優先序的依據）

> 🔴 **這組數字不可作為優先序依據**（Decision Log #4，2026-08-16 更正）。

> 89 次 AI 使用是自我測試的痕跡，0 次 GPU 任務是「還沒有人試過」，
> 3 個使用者是測試帳號。把它當成使用行為會推導出假的優先序。
> **v2 的優先序改由「意圖」決定，不由「證據」決定**，見第 2 節。

## 2. 優先序與主線

**優先序不由使用資料推導**（Decision Log #4：資料是開發期自測痕跡），
改由擁有者依「希望新學生第一次做什麼」裁定。

### 主線任務

> **學生想問 AI，而且要在問之前知道自己還剩多少點。**

檢驗：如果只有這一件能動，平台仍值得打開。理由是擁有者的判斷——
「詢問 AI 一定是最多人使用的功能」（Decision Log #7）。

### 三層

| 層級 | 任務 |
|---|---|
| **主線** | 問 AI（→ MYAI）· 點數餘額（是前置條件，不是獨立功能） |
| **支援**（少了它主線不完整） | 登入（SSO／admin 本機）· 點數餘額 · 小基（RAG 助手） |
| **邊緣**（目前只需要是入口） | Lab · 送 GPU · 上傳資料集 · 任務進度 · Secrets · 磁碟配額 · 文件庫 · 公告 · 設定 · 問題回報 · 使用量明細 · 自動開通確認 |

### GPU 不靠版面權重保命

擁有者提過「A/B 雙主線」，**未採用**。理由：v1 已經是事實上的多主線
（五個分頁各佔完整版面），結果是沒有任何一個被凸顯，GPU 依然 0 次使用。
**並列不會讓東西被看見，只會讓兩個都變成背景**；兩個同權動作會讓使用者
停下來選，而不是動作。

「是主線」是**版面權重**問題，「不被遺忘」是**發現性**問題——用前者的解法
去解後者，就是 v1 的做法。改用兩個機制（Decision Log #8）：

| 機制 | 內容 |
|---|---|
| **甲 · 入口卡帶具體成果** | 首頁一張卡，文案是成果而非功能名：**「訓練你的第一個影像分類模型」**。「運算任務」說明不了任何事；人是被成果吸引的 |
| **乙 · 時機式出現** | 使用者在 Lab 寫完程式的那一刻才出現「送 GPU 跑」——這正是鐵則 #4 的形狀 |

未採用「丙·角色預設」：目前只有 3 個測試帳號，沒有依據判斷角色與需求的對應。

## 3. 慣例（Jakob's Law）

對照對象以「**可檢視**」為選取標準（有官方文件或部署說明），不憑印象。

| | Open OnDemand（大學 HPC 入口） | Google Colab（筆記本＋GPU） | JupyterHub（機構型啟動器） |
|---|---|---|---|
| 主導覽 | 頂部橫列 | 頂部選單列 | 極簡（幾乎沒有） |
| 首頁是什麼 | 儀表板：公告＋**配額用量**＋系統狀態，一眼可見 | 不適用（直接進筆記本） | **只有一到兩顆按鈕：啟動／停止你的 server** |
| 功能入口形式 | **Pinned Apps 磁磚** | 頂部選單 | 按鈕 |
| 側邊欄 | — | 左側放檔案與目錄（脈絡用，非主導覽） | — |

來源：[Open OnDemand 簡報](https://www.openondemand.org/sites/default/files/documents/Introducing%20Open%20OnDemand.pdf)、
[FSU OOD 部署說明](https://docs.rcc.fsu.edu/hpc/ood/)、
[Colab 介面](https://py.imagej.net/en/latest/Google-Colab-Basics.html)、
[JupyterHub 文件](https://jupyterhub.readthedocs.io/en/stable/howto/configuration/config-user-env.html)

### 照抄清單（三者一致，不辯論）

1. 主導覽放**頂部**。Colab 的左側欄放檔案，不是導覽。
2. **首頁＝啟動器，不是內容頁。** 沒有一個對照產品把首頁做成資訊看板。
3. **配額／狀態在首頁一眼可見**（OOD 明確做此設計）。
4. **功能入口用磁磚或按鈕，不用分頁。** ← 直接否定 v1 的做法：
   分頁的語意是「同一件事的不同面向」，不是「不同的事」。

### 決定清單（對照產品分歧＝我們真正的決定）

| # | 決定 | 裁定 | 理由 |
|---|---|---|---|
| D1 | 點數餘額放哪 | **貼著主要動作**，不做頂部常駐 | 常駐＝背景資訊＝被忽略；貼著動作才是決策資訊。按下去就離站，這是唯一看得到的時機 |
| D2 | 問 AI 與其他入口的關係 | **唯一主要動作**，其餘次級磁磚 | 主線只有一個；兩個同權就是 v1 的錯 |
| D3 | Lab 怎麼開 | **同頁顯示啟動狀態 → 就緒後新分頁** | 容器要 5–10 秒，直接開新分頁會看到空白 |
| D4 | 使用量明細怎麼開 | **獨立頁**，頁首重述當前額度 | 有圖表要空間；重述額度是 C3 修正——使用者是「看著額度覺得快沒了」才點進來的 |

未採用 OpenAI Platform 作為第三對照：搜尋只查到功能（即時成本圖、日期篩選、
依模型拆分、可匯出 CSV），**查不到版面位置**，屬二手描述，不足以當版面慣例。
那幾個功能點對 D4 的內容組織仍有參考價值。

### Token 架構（為了「後期方便調整」）

擁有者要求「盡可能做成後期方便調整的」（Decision Log #18）。做法是**兩層 token**：

```
第 1 層 · 原始色階     --mcu-yellow-500: #f9bf3b;   ← 只是顏色，不帶用途
                      --mcu-slate-600:  #4d5f85;

第 2 層 · 語意 token   --accent:      var(--mcu-yellow-500);   ← 這是「主要動作的底色」
                      --on-accent:   #1f2328;                 ← 「疊在 accent 上的字」
                      --surface:     #ffffff;
                      --surface-2:   #f3f5f9;
                      --text:        #555555;
                      --hairline:    #e9e9e9;

元件只准用第 2 層。
```

**為什麼分兩層：**

- 換色系 = 只改第 2 層的映射，不動任何元件 CSS
- 微調某個顏色 = 只改第 1 層一個值，全站跟著變
- **元件裡不准出現色碼**——今天才踩過「改了沒效果」的坑（同一個 class 定義兩次，
  後者勝出）。色碼散落各處會製造同一類問題，而且更難查

切換機制：`<html data-theme="yellow|blue">`，
以 `:root[data-theme="blue"] { --accent: ...; --on-accent: ...; }` 覆寫**第 2 層**。
預設（無屬性）即黃色系。
