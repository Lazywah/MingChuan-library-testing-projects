# 00 — 本機完整部署指南（單機 PC / Windows + Docker Desktop）

> 本文記錄在**單一 PC** 上把整個平台（核心服務 + AI 模型 + GPU 訓練）完整跑起來的
> 所需工具、環境、啟動步驟、測試結果，以及部署過程中發現並修正的問題。
> 撰寫時的實測環境：**Windows 11 + Docker Desktop + NVIDIA RTX 4060（8GB）**。

---

## 1. 所需工具 / 環境

| 項目 | 需求 | 備註 |
|---|---|---|
| OS | Windows 10/11（或 Ubuntu 22.04+） | 本指南以 Windows + Docker Desktop 為主 |
| Docker | Docker Desktop（含 Compose v2） | 實測 Docker 28.x / Compose v2.39 |
| WSL2 | 啟用（Windows） | Docker Desktop 勾「Use WSL 2 based engine」|
| GPU（選用） | NVIDIA GPU + 驅動 | 沒有 GPU 也能跑（Ollama/訓練改 CPU，較慢）|
| NVIDIA GPU passthrough | `docker run --rm --gpus all nvidia/cuda:12.3.0-base-ubuntu22.04 nvidia-smi` 能看到 GPU | Docker Desktop 通常自動具備 |
| 磁碟空間 | ≥ 60–80 GB | base images ~20GB×數個 + llama3 4.7GB + open-webui 等 |
| RAM | ≥ 16 GB（建議 32GB） | |

> **GPU 記憶體提醒**：8GB GPU 上 Ollama 載入 llama3（~7.5GB）後幾乎佔滿，**無法同時**跑
> GPU 訓練；本機測訓練時需先停 Ollama（見 §6）。架構正式設計是 GPU 節點與服務層分離。

## 2. 一次性設定（.env 機密）

服務層 `.env` 需含三把機密（缺一即 fail-fast 無法啟動）：`JWT_SECRET_KEY`、`WORKER_API_TOKEN`、`SECRETS_MASTER_KEY`。
本機已存在 `.env`（皆已設定）。若要重新產生：

```bash

```

雲端 API key（`ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GOOGLE_API_KEY`）目前留空 → 雲端模型預設不公開，
平台只用本機 Ollama。日後接 key 後在 admin 管理頁把對應模型設「公開」即可。

## 3. 完整啟動步驟（全新機器，依序執行）

> 🚀 **懶人包（Windows）**：跑完 `python scripts\setup_env.py` 與 `build-all.sh` 後，
> 直接執行 **`scripts\bootstrap.bat`** —— 它會自動依正確順序做 step (2)~(5)
> （起 AI 模型層 → pull 3 模型 → 起核心 → 建 admin → 驗證 KB）。下面是手動逐步版。

> ⚠️ 順序很重要：**先 build base images、先把 Ollama 模型 pull 好，再起核心**，否則
> ① Lab/訓練沒有 image 開不了；② 小基開機那次 KB 匯入會因模型未就緒而失敗。

```bash
cd CodeSpace

# (0) 一次性產生 .env 機密（互動式；產生根 .env 單一來源，gpu-worker 也讀它，不再另寫 gpu-worker/.env）
python scripts/setup_env.py

# (0.5) ⚠️ 手動貼上學校 SSO 憑證（setup_env.py 不會問、也生不出來——只有學校 IT 給得到）
#       編輯根目錄 .env，把 IT 提供的值填進去（只貼值、**同一行不要寫註解**）：
#         OIDC_CLIENT_ID=<IT 提供>
#         OIDC_CLIENT_SECRET=<IT 提供>
#       redirect/discovery 已有正確預設，通常不用動（詳見 §9）。
#       ⚠️ 沒填 = SSO 停用 = 學生一個都無法登入（admin 仍可從 :8888 進）。
#       （管理員密碼已在步驟 (0) 由 setup_env.py 設定並寫入 .env，這裡不用再處理）

# (1) Build base images（Lab + 各訓練環境）── ⚠️ 很耗時(可達數十分鐘)、需 vscode-extension/
#     沒有要用 Lab / GPU 訓練可暫時跳過；要用 Notebook 就一定要 build code-server
bash infrastructure/base-images/build-all.sh           # 產生 aibase/code-server、pytorch、tensorflow…
#     Windows 無 bash 時可用 Git Bash 執行，或逐一 docker build（見該腳本內容）

# (2) AI 模型層：ollama + portkey + open-webui
#     有 NVIDIA GPU → 疊加 GPU override 讓 Ollama 用 GPU：
docker compose -f docker-compose.ai-models.yml -f docker-compose.ai-models.gpu.yml up -d
#     無 GPU → 只用基礎檔（CPU，較慢）： docker compose -f docker-compose.ai-models.yml up -d

# (3) Pull 全部 3 個本機模型（缺任一都會有功能壞掉）
docker exec ai-platform-ollama ollama pull llama3:latest        # chat / 簡報
docker exec ai-platform-ollama ollama pull nomic-embed-text     # 小基 RAG 向量 (RAG_EMBED_MODEL)
docker exec ai-platform-ollama ollama pull qwen2.5:7b           # 小基 客服/家教回覆 (RAG_CHAT_MODEL)

# (3.5) 部署前健檢（非 IT 看綠燈）：必填秘鑰、設定漂移、gpu-worker 收斂、?v=、埠占用
#       🔴 有 FAIL 就別往下；🟡 只是提醒可續。
python scripts/deploy_check.py

# (4) 核心層：nginx(:80,:8888) + job-scheduler(:8002)  ── 會 build scheduler image
#     此時 Ollama+模型已就緒 → scheduler 啟動時會自動匯入知識庫 (KB)
docker compose up -d --build
#     （若 (4) 不慎早於 (2)(3) 執行 → KB 會是空的，補：docker compose restart job-scheduler，
#       或 admin token 打 POST /api/v1/assistant/reindex）

# (5) 管理員帳號 —— v3.3 起「不需手動建立」
#     步驟 (0) 的 setup_env.py 會請你設定密碼並寫入 .env；核心首次啟動時，
#     若資料庫「完全沒有任何 admin」→ 自動建立帳號 admin（密碼即你當時輸入的）。
#     驗證：docker logs ai-platform-scheduler | findstr 初始管理員
#
#     只有這些情況才需手動執行（救援用，密碼改為執行時輸入）：
#       - setup_env 時把密碼留空 → 沒有自動建立
#       - 忘記密碼 / 所有管理員都被刪除，需要重設
#     scripts\create-admin.bat

# (6)（選用，需 GPU）GPU 訓練 Worker
#   設定單一來源＝根 .env（不再有 gpu-worker/.env）。用包裝腳本啟動，它會自動帶 --env-file ../.env，
#   勿在 gpu-worker/ 直接 docker compose up（會誤用不安全預設 token → 已設 fail-fast 會直接報錯）。
cd gpu-worker
./start-worker.sh up -d --build      # Windows：start-worker.bat up -d --build（首次含 --build）
cd ..
```

啟動後容器應有：`ai-platform-nginx`、`ai-platform-scheduler`、`ai-platform-ollama`、
`ai-platform-portkey`、`ai-platform-webui`、（選用）`mcu-gpu-worker`。

## 4. 部署中發現並修正的問題（已寫回設定/程式）

| # | 問題 | 修正 |

| 1 | `/api/v1/models` 回 502（nginx 漏掛該前綴 location，落到 Open WebUI） | `infrastructure/nginx.conf` 補 `^/api/v1/models` location |

> Ollama GPU 加速採**選用 override 檔** `docker-compose.ai-models.gpu.yml`（基礎檔維持 CPU 可攜）。

## 6. 單機 GPU 注意事項（重要）

8GB GPU 上 **Ollama 與訓練無法同時用 GPU**：
- 跑聊天/簡報 → Ollama 佔 GPU（正常）。
- 要測/跑 **GPU 訓練** → 先釋放 GPU：`docker stop ai-platform-ollama`，跑完再 `docker start ai-platform-ollama`。
- 桌機 GPU 還會被 OS/瀏覽器佔用，故 worker 的「空閒判定」門檻已可調：**根 `.env`** 的
  `GPU_IDLE_UTIL_THRESHOLD`（單機設 90；**專用 GPU 節點請保持 10**）。

正式環境建議：GPU 訓練放**獨立 GPU 節點**（headless，GPU 真正閒置），服務層只跑推理。

## 6.1 `mcu-gpu-worker` 的生命週期（獨立節點，平時不需手動關閉）

`mcu-gpu-worker` **刻意獨立於核心 stack**：它有自己的 compose（`gpu-worker/docker-compose.yml`）與獨立 network，模擬一台**遠端 GPU 運算節點**——正式環境會跑在另一台機器上，透過網路向服務層輪詢領取訓練任務。因此 `docker compose down`（核心）**不會**連帶停掉它。

**需要手動關閉嗎？平時不用。** 設計如下：

| 行為 | 說明 |
|---|---|
| `restart: unless-stopped` | Docker Desktop 開機時**自動拉起**，並持續存活直到你手動 `stop`。這也是為何核心 stack 已 down、它卻仍 `Up`。 |
| 核心未啟動時 | 每 `HEARTBEAT_INTERVAL`（預設 30s）對 `:8002` 心跳失敗一次，僅寫一行 WARNING log。**GPU 用量為 0**（worker 只有 `utility` 能力跑 `nvidia-smi`，本身不訓練），幾乎不耗資源。 |
| 核心恢復後 | scheduler 一起來，心跳**自動恢復**、繼續領任務，無需重啟 worker。 |

**只有這兩種情況才需要手動停：**
```bash
# (a) 長時間關閉整個平台、不想看到它持續重試的 log（暫停，Docker 重啟後仍會自己回來）
docker stop mcu-gpu-worker

# (b) 真的要它「不再自動啟動」（移除容器，需重新 up 才會回來）
cd gpu-worker && ./start-worker.sh down && cd ..
```
> 注意 (a) 因 `unless-stopped`，**重啟 Docker 後 worker 會自己回來**；要徹底不自啟，請用 (b) 的 `compose down`。

> 判讀：`nvidia-smi` 的 compute-apps 清單若**只有桌面程式**（explorer / 瀏覽器 / Wallpaper Engine…）而無 Ollama / 訓練容器，代表平台層 GPU 負載為 0，顯存佔用是桌面 app，與 worker 是否在跑無關。

## 6.2 外部 AI 分流（v2.5 — 角色 gate + 帳號對應表）

自家 AI 助手成熟前，可暫時以合作廠商（如 myai168）替代給**非 admin 使用者**。廠商無 API/SSO、不可內嵌（`X-Frame-Options: SAMEORIGIN` + CSP `frame-ancestors 'self'`），故採「**導流 + 帳號對應表**」：

- **角色分流**：只有 `admin` 角色看得到內部 AI hub（chat/簡報，用於繼續開發）；其餘角色點「AI 助手」分頁 → 顯示**外部中介頁**（指派帳號 + 「前往」開新分頁；明示對話不在本平台留存）。
- **帳號對應**：平台帳號 ↔ 廠商帳號為兩套、無法 SSO 打通；admin 在廠商後台造冊後，於 admin-ui 維護對應。**不保管學生自選的密碼**。
  > ⚠️ **v3.3 更新**：新增「自動開通」（首次 SSO 登入即透過廠商**官方批次註冊**建號並綁定），因此系統會**暫存一組系統產生的初始密碼**（AES-256-GCM 加密，預設 30 天或學生按「我已修改」後即銷毀）。這是**憑證遞送**，與「保管學生密碼」不同；學生改過密碼後該值即失效。功能由 admin 系統設定的 `myai_autoprovision` 控制，**預設關閉**。
- **總開關（回退）**：`system_config.external_ai_url`。**空字串 = 未啟用**，使用者端中介頁顯示「即將開放」；自家 AI 成熟後清空即切回，內部 chat 程式碼全程不動。

**管理流程（admin-ui → 右側 Side Bar「外部 AI」分頁）：**
1. **設定網址**：填入廠商平台網址（如 `https://www.myai168.com/tw/ai/`）→ 儲存。留空 = 停用。
2. **造冊匯入**：「CSV 批次匯入」貼上 `platform_username,vendor_username`（每行一筆，可含表頭，重複者更新）→ 匯入。或用「新增單筆對應」。
3. **維護**：對應表可「改帳號 / 停用·啟用 / 刪除」；停用者使用者端顯示「請聯絡管理員」。

> 端點：使用者 `GET /api/v1/external-ai/me`；管理 `/api/v1/external-ai/admin/{url,accounts,import}`（皆 `require_admin`）。新表 `external_ai_accounts` 由 `init_db()` 自動建立；`external_ai_url` 由 seed 預設 MYAI 網址（可於管理頁清空回退）。

### 6.2.1 廠商 Token 同步 + Email 綁定（v2.8）

在「導流 + 對應表」之上，v2.8 補上**唯讀同步**與**顯式 email 綁定**：

- **headless 同步（唯讀）**：以管理者帳密（`.env` 的 `MYAI_ADMIN_EMAIL` / `MYAI_ADMIN_PASSWORD`）headless 登入 myai168 後台 → 匯出使用者清單（含「點數」= Token 餘額）→ 存進 `myai_accounts`。**全程唯讀，絕不回寫廠商**。可「立即同步」，或由排程每 `MYAI_SYNC_INTERVAL_HOURS` 小時（預設 6；設 0 關閉）自動跑。
  - ⚠️ **登入眉角**：myai 有 `form-action 'self'` 防跨站，登入 POST 必須帶正確 `Referer`/`Origin` 標頭，否則回 200 卻不發 session cookie（見 `services/myai_sync.py`）。
- **Email 綁定 / auto-match**：以 email 對應「平台使用者 ↔ myai 帳號」，存於 `external_ai_accounts`（`vendor_username` = myai email，`myai_vendor_sn` = 廠商穩定鍵）。同步後自動配對；admin 也可在「外部 AI」分頁「一鍵 Email 配對」、查看「未配對清單」、手動綁/解綁。**只寫本平台 DB**。
- **使用者端 Token 餘額**：AI 助手中介頁顯示「AI 點數餘額」（有綁定且同步到資料才顯示）。
- 端點：`/admin/{sync-myai,myai-accounts,auto-match,bindings,unmatched}`（皆 `require_admin`）。

### 6.2.2 跳轉登入 + 共用機台換手安全（v2.8）

**為何沒有「真・帳密自動登入」**：myai 登入要 email + 密碼，我們**不代學生送出密碼**（資安原則；那等於平台經手他的密碼）。OAuth 僅供 AI 推論（scope `mcp`），非使用者 SSO。故自動化只到「**導流 + 顯示該用哪個 email + 提醒**」，密碼由學生自行輸入或瀏覽器密碼管理員處理。
> v3.3 起若啟用自動開通，學生首次登入會在 AI 助手頁看到系統產生的**初始密碼**（可複製），仍需他自己到廠商站台登入並修改；平台不會代填。

**共用機台（圖書館／實驗室多人輪用同一台）務必注意換手**，否則下一位可能延續上一位的登入。重點：**「直接關掉瀏覽器」預設不等於登出**——一般登入會持久保留（localStorage / 持久 cookie），故 v2.8 做了三層防護：

1. **token 不持久化（B，已做）**：web-ui 登入憑證改存 **sessionStorage**、`/code/` cookie 改為 **session-cookie（無 `max_age`）** → **關閉瀏覽器即失效**，不跨重開保留（JWT 另有 `exp` 把關）。開機時也會清掉舊版殘留在 localStorage 的 token。
2. **主動換手（結束使用按鈕）**：AI 助手中介頁「**結束使用 / 換人**」→ ① 開廠商登出端點殺掉 myai session ② 登出本平台、清 `ai_hud_token`（sessionStorage + cookie）③ 提醒關閉 MYAI 分頁。
   - 廠商登出端點（**已驗證**）：`https://www.myai168.com/mcu/ai/user/logout_info`（GET 即清；實測登出前 export 200、登出後 401）。存 `system_config.external_ai_logout_url`，admin 可於「外部 AI」分頁調整；`/external-ai/me` 回傳給前端。
3. **無痕捷徑（D，零 IT，最終保證）**：`scripts/建立桌面捷徑.bat`（改好 `PLATFORM_URL` 後執行）在桌面建立 **以無痕／InPrivate 開啟本平台** 的捷徑（Chrome `--incognito` 為主、Edge `--inprivate` 次之，偵測到誰建誰）。學生雙擊→無痕視窗→**用完直接關閉視窗，cookie/localStorage/sessionStorage 全清（本平台 + MYAI 一起）**，不嵌帳密、不靠手動登出、不需系統管理員。
   - 前提：學生一律用此捷徑開、勿另開普通視窗；若該機已被企業政策停用無痕，才需有權限者調整。
   - 等效替代（需一次本機管理員）：瀏覽器政策 `ClearBrowsingDataOnExitList`（關閉自動清）。

## 6.3 RAG 客服/導覽助手「小基」（v2.6 — 右下角浮動泡泡）

獨立於主「AI 助手」入口的浮動客服泡泡，以 RAG（`job-scheduler/knowledge/*.md` + 本機 Ollama）回答平台使用問題。`/api/v1/assistant/ask` **公開、不扣 Token、限流 30/分、直接打 Ollama 不經 Portkey**。

⚠️ **三個「不做會無聲失敗」的部署前置（最容易漏）：**

1. **rebuild scheduler image（不是只 restart！）**——知識庫是 `Dockerfile: COPY knowledge/ /app/knowledge/`（build 時打包），compose **未掛載** `knowledge/`。若 image 在 `.md` 出現前 build，容器內 `/app/knowledge` 會是空的（log 顯示 `KB status: empty`）。
   ```bash
   docker compose up -d --build job-scheduler   # 把 knowledge/*.md 打進 image
   ```
   > 開發時若想免 rebuild 即時更新 KB，可在 compose 的 job-scheduler `volumes:` 加 `- ./job-scheduler/knowledge:/app/knowledge:ro`（與 app/ 熱掛載同理）。
2. **Ollama 必須在跑，且 pull 兩個模型**（否則客服不回話、看似壞掉）：
   ```bash
   docker compose -f docker-compose.ai-models.yml -f docker-compose.ai-models.gpu.yml up -d
   docker exec ai-platform-ollama ollama pull nomic-embed-text   # RAG_EMBED_MODEL（向量）
   docker exec ai-platform-ollama ollama pull qwen2.5:7b          # RAG_CHAT_MODEL（回覆）
   ```
3. **nginx 已補 `/api/v1/assistant` location**（v2.6 整合修正）——`/ask` 是 SSE，須關 buffering；缺此 location 時 widget 經 :80 會 502（同 `/api/v1/models` 類問題）。已內建於 `nginx.conf`，**改 conf 後記得 `nginx -s reload`**。

**驗證 / 維運：**
```bash

curl -N -X POST -H "Content-Type: application/json" -d '{"question":"如何登入"}' http://localhost/api/v1/assistant/ask   # 應回 200 text/event-stream
# admin 重建知識庫（改 knowledge/*.md 後）：POST /api/v1/assistant/reindex
```

### v2.7 程式家教模式（Notebook 程式輔導）

小基新增第二模式，右下角泡泡可切換「客服 ⇄ 程式家教」：

- **guide（客服）**：維持原狀（公開、不需登入、不扣 token）。

- 入口：泡泡上方模式鈕，或「Compute Tasks → Notebook」頁的「問程式家教」按鈕（`window.AibotWidget.openCodeMode()`）。
- **Lab 內嵌檢視（v2.7）**：「進入 Notebook」改成把 code-server **內嵌進頁面 iframe**（不再另開分頁），小基泡泡(z-index 10000)即浮在 Lab 上面 → 真正「在 Lab 內就能問」。toolbar：收合 / 全螢幕 / 新分頁開啟 / 停止。可行性已實測：`/code/` 同源、無 frame 阻擋、cookie 認證、WebSocket 皆 OK，純前端、不動後端/nginx。注意 VS Code 在 iframe 須**載入時即有非 0 尺寸**才會正確渲染（本流程的按鈕在可見頁面上，已滿足）。
- **改前端資產記得 bump `index.html` 的 `?v=` 版本**（cache-buster），否則瀏覽器會用舊的 `app.js`/`assistant-widget.js`/`styles.css`。
- **KB 熱掛載（v2.7）**：compose 已加 `./job-scheduler/knowledge:/app/knowledge:ro` → 新增/修改 `.md` 後**只需** `POST /reindex`，**免 rebuild**。目前 8 檔 / 40 chunks。


## 8. 疑難排解

| 症狀 | 可能原因 / 處置 |
|---|---|
| `/api/v1/...` 回 502 | 對應後端容器未起 / nginx 缺該前綴 location（見 §4-#1）|
| 聊天無回應、scheduler log 顯示 Portkey 連線失敗 | Portkey 未起或 port 不對（須 8787，見 §4-#2/#3）；`ollama list` 確認 llama3 已 pull |

| Lab「開啟 Notebook」失敗 | 確認 `aibase/code-server:2026-spring` image 已 build、docker.sock 已掛載 |

## 9. 學校 SSO 上線（v3.1 — MCU 自建 OIDC）

> ⚠️ **這是空機部署最容易卡住的一步**：`sso_policy.yaml` 已設定為 `provider: oidc` /
> `mock_mode: false`。**若 `.env` 沒有 OIDC 憑證，學生一個都無法登入**
> （系統會 fallback 成 mock、`/api/v1/sso/providers` 回 `[]`，登入頁顯示「系統登入功能尚在設定中」）。
> 此時 **admin 仍可從 :8888 以本機帳密登入**。`python scripts/deploy_check.py` 會直接把這個狀態標成黃燈。

**MCU 用的是自建 OIDC（`auth.mcu.edu.tw`），不是 Microsoft Entra。** 端點由 discovery 自動取得。

1. **向學校 IT 申請**（範本見 `docs/IT-OIDC-申請信範本.md`），取得 `client_id` / `client_secret`，
   並確認 redirect URI 已註冊為本平台的 nginx origin：
   - dev：`http://localhost/api/v1/sso/oidc/callback`
   - prod：`https://<正式主機名>/api/v1/sso/oidc/callback`
   > ⚠️ **絕不可用 `:8002`**：那是 API 直連埠，不服務 `/V0/`，登入後會 404。
2. **填入根 `.env`**（只填值、**不要把註解寫在同一行**）：
   ```
   OIDC_CLIENT_ID=<IT 提供>
   OIDC_CLIENT_SECRET=<IT 提供>
   OIDC_REDIRECT_URI=http://localhost/api/v1/sso/oidc/callback
   OIDC_DISCOVERY_URL=            # 留空＝用 sso_policy.yaml 內建的 auth.mcu.edu.tw
   ```
3. **重啟並驗證**：
   ```bash
   docker compose up -d job-scheduler
   curl -s http://localhost/api/v1/sso/providers        # 應回 {"providers":["oidc"]}
   ```
4. **身分對應**：MCU 的 userinfo **只回 `{"sub": "<學號>"}`**（無 email/姓名），
   故平台帳號 = 學號，email 以 `sso_policy.yaml` 的 `email_domain` 補成 `<學號>@me.mcu.edu.tw`
   （與 MYAI 綁定用的信箱一致）。
5. **密碼相關**：SSO 帳號不能在本平台改密碼；「忘記密碼」導向學校中央入口
   `https://www1.mcu.edu.tw/ForgetPassword.aspx`（學號＋身分證字號 → 新密碼寄校務系統信箱）。

### 9.1 ⚠️ 部署範圍：目前學生端只能在「伺服器本機」使用

`redirect_uri` 是給**瀏覽器**去的地址。設成 `http://localhost/...` 時，
`localhost` 永遠指「開瀏覽器的那台電腦」——學生從自己的筆電登入，IdP 會把他導回
**他自己的** localhost，登入必然失敗。且 `web-ui` 自 v2.1 起已無本機帳密表單，
學生沒有 SSO 以外的登入途徑，故**其他電腦目前完全無法使用**。

- **不受限**：GPU worker（主動連 `SERVICE_LAYER_URL`，機器對機器）→ **現在就能跨機部署**。
- **可跨機但不建議**：admin `:8888` 走本機帳密可從別台登入，但目前是 http，
  **管理員密碼會明文過網路**；補上 HTTPS 前請只在本機使用。

要開放給其他電腦，需要主機名 + 憑證 + nginx:443 + IdP 加註冊 —— 詳見
[`03-deployment.md`](03-deployment.md) §2.3 / §2.4（含「為什麼一定要 HTTPS」的說明：
登入權杖是以 `/V0/?sso_token=` 寫在網址列交付的，http 會被同網段側錄）。

**停用 vs 刪除（重要語意）**
- **停用**（admin 設 `is_active=0`）＝懲罰性停權，**登入階段就會被擋**並顯示明確訊息。
- **刪除**對 SSO 使用者**不等於封鎖**：學校 SSO 才是身分權威，該生下次登入會以**新 uuid** 自動重建帳號
  （role 回 student、Lab 換成新的空間）。要擋人請用**停用**。

## 10. 新增的營運功能（v3.2 / v3.3）

### 10.1 GPU 節點可排程時段（admin →「GPU 節點」分頁）
- 每個 worker 首次心跳會**自動出現**在該分頁，預設「啟用 + 全天可排」（行為與加此功能前一致）。
- 可設：總開關、每週時段（支援跨夜）、池別覆蓋、**停派緩衝**（時段結束前 N 分鐘不再派新工作）。
- **到點政策 = drain**：只擋「新派工」，執行中的任務會**跑完**，不會被中斷。
- 時段一律以**台北時間（UTC+8）**判定（容器時鐘是 UTC，程式內已換算）。
- ⚠️ **NODE_ID 必須每台唯一**（`.env` 範本預設 `gpu-node-01`）。多台抄同一個 ID 會互蓋狀態，
  系統偵測到會在 admin 顯示紅色橫幅。

### 10.2 帳號刪除與 Lab 資料封存（admin →「Lab 管理」分頁底部）
- 刪除帳號時，其 Lab volume **不會立即銷毀**，而是「原地封存」預設 **30 天**（`lab_archive_days` 可調）。
- 期間可在 admin **還原**給任一使用者（因 SSO 使用者回來是新 uuid，還原＝把資料複製進對方現有的 Lab），
  或**立即銷毀**。逾期由每日維護任務自動清除。
- 還原會用到 `alpine:3.19` image；**離線環境請先 `docker pull alpine:3.19`**。

### 10.3 維運腳本（需在 scheduler 容器內執行）
`scripts/` 已唯讀掛載到容器的 `/app/scripts`（需同時存取 DB 與 docker socket）：
```bash
# Lab volume 盤點（使用中 / 封存 / 舊命名 / 孤兒）；預設只列出不刪
docker exec ai-platform-scheduler python /app/scripts/cleanup_lab_volumes.py
docker exec ai-platform-scheduler python /app/scripts/cleanup_lab_volumes.py --adopt --apply
```

### 10.4 MYAI 自動開通（預設**關閉**）
- 開啟後，學生首次 SSO 登入會透過廠商**官方批次註冊**自動建號並綁定，初始密碼顯示在其 AI 助手頁。
- 由 admin「系統設定」的 `myai_autoprovision` 控制；`myai_initial_credit` 預設 0（不發點數）。
- ⚠️ **目前尚未完成**：廠商批次註冊的「確認送出」段待實測補完，功能旗標請維持 0。
