## 這三版是什麼

| | 對外路徑 | 檔案 | 程式行數 | 近三個月 commit |
|---|---|---|---|---|
| **v1** | `/V0/` | `web-ui/` | 5 個檔（單頁式）| 6,459 | 49 |
| **v1.5** | `/V0.5/` | `web-ui-V0.5/` | 5 個檔（單頁式）| 6,447 | 6 |
| **v2** | `/V1/` | `web-ui-V1/` | 30 個檔（11 個頁面）| 4,638 | 17 |

三版**共用同一個後端、同一份資料**。使用者在哪一版做的事，另外兩版都看得到。

- v1 / v1.5 是**單頁式**：一個 `index.html` + 一支 6,400 行的 `app.js`，用分頁切換
  （首頁 / 儀表板 / AI 助手 / 文件 / 設定）。
- v2 是**多頁式**：每個畫面一個 html + 一支對應的 js，共用 `chrome.js`（導覽）、
  `prefs.js`（偏好）、`i18n.js`（雙語）、`tz.js`（時區）。

---

## 🔴 先講一件影響決策的事：v1 與 v1.5 的功能**完全相同**

逐項比對三十一個功能，**沒有任何一項是其中一個有、另一個沒有的**。

兩者的差異只有三類，**沒有一類是新能力**：

1. **送出訓練任務那張表單拆成兩份**（`-high` / `-midlow` 後綴），
   對應 v3.0 的高階 GPU / 本地 GPU 池別路由
2. **補上無障礙標籤與翻譯 key** —— `aria-label`、`placeholder`、
   「快速入口」的標題字串等等
3. CSS 微調

⚠️ 第 2 類容易被誤讀成「v1.5 多了字體大小控制與快速入口」。**不是**：
兩版都有那兩樣東西（`document.documentElement.style.fontSize` 與
`.bottom-quick-links` 在兩邊都在），v1.5 只是替它們補上了標籤與 key。
（這一點我第一輪就是這樣誤判的，回去比對原始碼才改正。）

檔案層級：`app.js` 差 100 行、`index.html` 差 186 行、`styles.css` 差 173 行；
`tz.js` 與 `assistant-widget.js` **逐位元組相同**。

也就是說：**v1.5 是 v1 的無障礙／版面調整版，不是功能增強版。**
近三個月 v1 有 49 個 commit、v1.5 只有 6 個 —— 實際在維護的是 v1，
而 v1 的每一次改動理論上都該同步到 v1.5（那 6 次顯然沒有全部跟上）。

## 取捨分析

### v1.5 是最容易處理的一個

它與 v1 **功能完全相同**，差別只有一張表單的版面。而且：

- 近三個月 v1 改了 49 次、v1.5 只跟上 6 次 —— 已經在漂開
- 每一次改 v1 都要記得同步 v1.5，而「記得」不是機制
- 它存在的理由是「新舊對照」（nginx 註解明講），而對照的對象是 v1，
  不是 v2

**如果要砍一個，v1.5 的代價最低、收益最明確。**

### v1 與 v2 現在還不能互相取代

- v2 缺的那 7 項裡，**站內 AI 對話、Token 配額、密鑰管理、新手導覽**
  是有人在用就不能少的
- v1 缺的那 5 項裡，**內建訓練、資料集管理、模型下載**是這一輪剛做完的主力功能，
  而且「傳滿 2 GB 沒辦法刪」在 v1 是實際會卡死人的

換句話說：**現在把 v1 關掉，會拿掉四個功能；把 v2 關掉，會拿掉整條
「不會寫程式也能訓練」的路。** 兩邊都不該現在關。

### 可能的路徑

| 做法 | 代價 | 適合什麼情況 |
|---|---|---|
| **只砍 v1.5** | 最小。改 nginx 一個 location + 刪一個目錄 | 想立刻少維護一份 |
| **把 v2 缺的 7 項補齊，再砍 v1** | 中～大。站內對話與新手導覽是大工程 | 決定 v2 是唯一未來 |
| **v1 與 v2 分工並存** | 需要講清楚「什麼事去哪一版做」 | 兩邊各有不可取代的功能 |
| 全部維持現狀 | 三份要同步，而三份不會同步 | ⚠️ 不建議 |

⚠️ **不論選哪條，v1.5 都應該先處理** —— 它是唯一一個「功能上完全多餘」的版本。

## 這份對照是怎麼做出來的（供覆核）

判準用「功能在程式碼裡一定會留下的痕跡」逐項比對，不是憑印象或看畫面。

⚠️ **過程中用單一正則抓端點連續漏報了三次**，都是寫法不同造成的：

- v2 用 `get('/jobs/pool-availability')`，不是 `${API}/...` 模板字串
- v1 用 `_api('/start')` 這種**帶前綴的 helper**（`/api/v1/lab` 在函式裡）
- `${API_BASE}/models` 與 `${API}/reports` 沒被引號判準抓到

所以最後改成**逐項用各自的證據去找**，而且每一格可疑的都回去看原始碼確認。
被這樣抓出來的假陰性有五個（模型清單、問題回報、文件庫、新手導覽、忘記密碼），
若直接發布會得出「v2 沒有問題回報」「v1 沒有文件庫」這種相反的結論。

**若要覆核**，這幾條指令對應表裡最吃重的幾格（在 `CodeSpace/` 執行）：

```bash
# v2 沒有站內 AI 對話（無輸出＝確實沒有）
grep -l "chat/completions" web-ui-V1/*.js

# v1 沒有資料集刪除（只會看到 datasets/upload）
grep -oE "datasets/[a-z]*" web-ui/app.js | sort -u

# v2 沒有 Token 配額顯示（無輸出＝確實沒有）
grep -oE "tokens_(used|limit)|auth/usage" web-ui-V1/*.js

# v1 的文件庫是寫死的佔位
grep -A 30 'id="docs-page"' web-ui/index.html | grep "內容建置中"

# v1 與 v1.5 的差異範圍
for f in app.js index.html styles.css tz.js assistant-widget.js; do
  echo "$f: $(diff web-ui/$f web-ui-V0.5/$f | grep -c '^[<>]') 行"
done
```
