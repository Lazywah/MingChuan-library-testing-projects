## 0. 進入管理端

`http://<主機>:8888/`

> ⚠ 管理端與使用者端是**兩個不同的入口**，登入狀態也是分開的
> （cookie 名稱不同）。在使用者端登入不等於管理端登入，反之亦然。

五個分頁：**總覽 · 帳號 · 平台設定 · 訊息 · 數據**。

右上角可以切**中／英文**。介面有些欄位旁邊有 **ⓘ**，點開是那一欄的說明。

## 1. 帳號

### 1.1 找人

三個來源分頁：本機帳號 / SSO / SSO（模擬）。
上方可以搜尋、依角色與狀態篩選。

> 清單一次最多 500 筆，超過要用篩選縮小範圍。

### 1.2 常見操作

| 想做 | 怎麼做 |
|---|---|
| 改角色或給管理權限 | 點該列 → 編輯 → 改「角色」或勾「管理員」 |
| 停用一個人 | 編輯 → 取消「啟用」 |
| 強制關掉某人的實驗室 | 該列的操作選單 |
| 個別加點 | 該列 → 加點（點數從平台的廠商管理帳號轉出，**不可逆**） |

### 1.3 臨時帳號

給校外人士、長官視察或其他例外用途。

- **一定要填用途** —— 半年後看到一個沒有用途的帳號，沒有人敢刪它
- 到期會自動停用，帳號與紀錄都留著
- 密碼**只會顯示一次**，關掉就看不到了

### 1.4 廠商帳號對應

平台的帳號與 MYAI 廠商帳號是**兩套**，靠這張對照表接起來。

| 按鈕 | 做什麼 |
|---|---|
| 同步廠商帳號 | 把廠商那邊的帳號與點數抓回來看 |
| 自動配對 | 把 email 相同的接起來（只寫平台這邊的對照表） |
| 用 CSV 批次建立對應 | 每行兩欄：`平台帳號,廠商帳號` |

> ⚠ 這兩個動作**都不會改到廠商的資料**。

下面三張小表分別是：平台使用者還沒綁定 / 廠商帳號沒對到人 / 可以開通。

### 1.5 刪除帳號

🔴 **不可逆**。刪掉之後：

- Lab 的存檔會**封存保留 30 天**（期限內可還原）
- 其餘資料消失
- 稽核紀錄保留但解除關聯

> ⚠ **SSO 帳號刪掉會自己長回來** —— 那個人下次登入時系統又幫他建一個。
> 要真的擋住某人請用「**停用**」，那才是懲罰。

## 2. 平台設定

### 2.1 營運設定（7 個旋鈕）

**改完立刻生效，不用重啟。** 留空 = 回到 `.env` 的預設值。

- 預設是**唯讀**，要按「編輯設定」才改得動
- 標 ★ 的表示「這個值使用者看得到，或改之前應該先發公告」

> 🔴 有兩個設定**刻意不在畫面上**：平台自己的月 Token 額度與重置日。
> 它們與學生在用的 **MYAI 點數無關**，並排會讓人以為調它們就能改學生額度。
> 要調請改 `.env` 的 `DEFAULT_MONTHLY_TOKEN_LIMIT` / `TOKEN_RESET_DAY`。

### 2.2 告警信

系統自己出事時（同步失敗、退信回收停掉）會寄這封信。

> 🔴 **收件人全部留空 = 完全不寄。** 目前就是這個狀態 ——
> 告警與退信回收都在跑，但沒有人收得到。上線前記得填。

### 2.3 GPU 節點

每台節點的狀態、可排程時段、開關、池別覆蓋。

- 時段用 `18:00-23:00, 08:00-12:00` 這種寫法，一天可以填多段
- 空白 = 那天不開放
- 有兩台機器用同一個 `NODE_ID` 時會出現🔴 警告 —— **派工會亂，要先改掉其中一台**

### 2.4 廠商模型代碼對應

廠商的備註欄給的是原始代碼（如 `gpt_5_6_sol`）。這張表只影響「數據」那一頁的
顯示與分群，**不會改寫原始交易紀錄**，改錯了隨時改回。

### 2.5 手動補齊點數

把所有綁定帳號補到**同一個點數水位**。

- 低於這個數字的才會補，補的是**差額**；已經高於的不動
- 重複執行不會重複發放
- 兩段式：先「預覽」，確認名單再「確認補齊」

> ⚠ **每月自動補點是另一回事**，在「系統設定」的 MYAI 那一組。
> 這裡按下去是**立刻執行**，不看補點日。

> 🔴 如果出現「送出了，但廠商沒有回報成功」—— **點數可能已經轉出**。
> 請到廠商後台對帳，**不要再按一次**。

### 2.6 組織對照表

學系 → 學院 / 行政單位 / 校區。「數據」那一頁的分群靠的就是這張表。

- 學院**不存在使用者身上** —— 改這裡全站立刻生效，不必回填任何人
- 可以匯出成 JSON 進版控，也可以匯回來（匯入會先預覽，**不刪除**既有資料）
- 停用只是不進下拉，既有的人仍然對得上
- 改名會把填過舊名的人一起搬過去，存檔後會告訴你搬了幾個

> ⚠ 這張表存在**資料庫**不跟 repo 走。換機器要帶 `data/ai_platform.db`。

## 3. 訊息

### 3.1 問題回報

- 點任一則會開**彈窗**，裡面是全文與回覆區
- 上方可依**類別**篩選（各有顏色）
- 🔴 **已回覆的變成唯讀** —— 回覆是單則的，而學生已經看到了，
  事後改掉等於偷偷換掉他讀過的東西
- **狀態仍然改得動**：「回覆了」與「處理完了」是兩件事

### 3.2 公告

「寫一則公告」會開**彈窗**（不會把清單推到很下面）。

| 欄位 | 說明 |
|---|---|
| 標題 / 內容 | 中文，**必填** |
| 標題 / 內容（英文） | **可留空**，空的話英文介面顯示中文版 |
| 置頂 | 排在最前面 |
| 公開 | 沒有勾的話**只有你看得到**，可以當草稿用 |
| 附件 | pdf / docx / xlsx / pptx / png / jpg / zip |

**內容是純文字**：貼 HTML 進去不會變成排版，會看到標籤本身；
但**貼網址會自動變成可以點的連結**。

**附件的限制**

- 單檔 20 MB、全站總量 2 GB（兩個都可以在系統設定裡改）
- 一則公告的附件數量**沒有上限**，但上傳頻率是每小時 30 次（以 IP 計算）
- 附件是**存檔之後**才送上去的（新公告在存檔前沒有可以掛附件的地方）
- 公告存成功但附件失敗時會**分開講**，並告訴你是哪幾個

> 🔴 刪掉公告時附件**立即刪除，不封存**。

### 3.3 寄信紀錄

看系統寄出的信與結果。

標題旁的 ⓘ 會告訴你退信回收的設定（伺服器、信箱、間隔）。
下面那一行是**最後一次**回收的結果。

> ⚠ 「已交付」不保證對方收到。網域存在但信箱不存在時會**稍後才退信**，
> 退信回收掃到之後會自己把狀態改成「已退信」。
> 🔴 但那個更新只有在**退信回收有啟用**時才會發生 —— 沒啟用的話狀態會
> 永遠停在「已交付」。畫面上那句「退信回收：未啟用」就是在講這件事。

## 4. 數據

上方可以選**期間**（快選或起訖日期），全頁共用。

### 4.1 MYAI 點數消耗

來自廠商的交易日誌（逐筆、含模型）。「向廠商重新同步」在右上角 ——
「資料看起來不對」十次有九次是還沒同步。

### 4.2 各分類使用

可切**學系 / 學院 / 行政單位**。表格分兩塊：

```
        │      這一組的人       │            用了多少
 學系   │ 人數 │ 有用的人 │ 滲透率 │ MYAI次數 │ MYAI點數 │ 訓練 │ Lab·GPU │ Lab·CPU │ 登入 │ Token
```

**兩個比例回答不同問題**：

| | 算法 | 用來看 |
|---|---|---|
| 佔比（括號裡的 %） | 這一組 ÷ 全平台 | 誰貢獻最多（**大系一定贏**） |
| 滲透率 | 有用的人 ÷ 這一組的人數 | **哪一組還沒推開** |

一個 500 人的系只要 10% 在用，佔比就比一個 30 人全用的系高很多 ——
所以要看滲透率才知道哪裡推得成功。

**三件要記得的事**（介面上的 ⓘ 也有寫）：

1. **滲透率的分母是「登入過平台的人」**，不是全系人數 → 這個數字**偏高**
2. **「有用的人」是下限** → 真實人數只會更多
3. **MYAI 次數與 Lab 的 GPU/CPU 之分自 2026-08-30 才開始記** →
   在那之前的 0 是「還沒開始記」，不是「沒有人用」

> 依**行政單位**分組時，名稱一律顯示中文（英文名只有 53/97，
> 補齊之前不做中英混雜）。

## 5. 上線前的檢查清單

| 項目 | 現況 | 上線要 |
|---|---|---|

## 6. 出事的時候

| 症狀 | 先看 |
|---|---|
| 整站 502 | `docker compose ps`，看 job-scheduler 是不是掛了 |
| 改了設定沒生效 | 是不是改了 `.env`？那個要**重啟**；系統設定頁的旋鈕才是即時的 |
| 前端沒更新 | 改過 JS/CSS 要跑 `python scripts/bump_assets.py` |
| 數據頁的數字怪 | 先按「向廠商重新同步」 |
| 有人說收不到信 | 訊息 → 寄信紀錄，看那一封的狀態 |

更完整的維運程序見 [04-operations.md](04-operations.md)。
